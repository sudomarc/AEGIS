# AEGIS ForgeHacks Scorecard

Use this before approving scope, after the first working prototype, and before submission.

## 1. Real-World Impact & Relevance

### Evidence
- [ ] Genuine problem identified.
- [ ] Specific target users identified.
- [ ] User scenario is concrete.
- [ ] Benefit is measurable or demonstrable.
- [ ] Claims are supported by sources or clearly labeled assumptions.

### Gate
Can a judge understand in under 30 seconds **who needs this, what hurts today, and how the product helps**?

## 2. Technical Implementation & AI Use

### Evidence
- [ ] AI/ML performs a meaningful task.
- [ ] AI is integrated into the product workflow rather than bolted onto the UI.
- [ ] Model choice is justified.
- [ ] Inputs/outputs are validated.
- [ ] Failure handling exists.
- [ ] Evaluation is measurable where applicable.
- [ ] Architecture is understandable.

### Gate
Can we explain why a simple rules-only system or generic chatbot would not provide the same value?

## 3. Innovation & Creativity

### Evidence
- [ ] Distinct problem framing or workflow.
- [ ] Useful combination of technologies.
- [ ] Differentiation is easy to demonstrate.
- [ ] Novelty improves the user outcome.

### Gate
Can we point to one concrete thing that makes the project meaningfully different?

## 4. Execution & Completeness

### Evidence
- [ ] Golden path works end-to-end.
- [ ] Error states are handled.
- [ ] UI is usable.
- [ ] Core behavior has tests.
- [ ] Browser verification completed.
- [ ] Deployment/demo path works.
- [ ] No obviously unfinished core feature.

### Gate
Can an evaluator use the project without us explaining how to bypass broken parts?

## 5. Presentation & Communication

### Evidence
- [ ] Video is 2–4 minutes.
- [ ] Demo starts from a real problem.
- [ ] The AI behavior is visible.
- [ ] Technical depth is explained simply.
- [ ] README matches the demo.
- [ ] Architecture diagram matches the actual system.
- [ ] Impact claims are defensible.

### Gate
Could someone understand the project after watching the video once, without opening the code?

## Feature approval rule

A feature enters scope only when it has:
1. a user/problem justification;
2. a rubric connection;
3. an owner;
4. a verification method;
5. a believable path to completion within the remaining hackathon time.

When these are missing, defer or remove the feature.
