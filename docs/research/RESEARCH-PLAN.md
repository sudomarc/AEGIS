# Pre-Hackathon Research Plan

## Objective

Prepare research inputs without locking the solution before the official ForgeHacks prompt.

## Research lanes

### A. Prompt analysis
At kickoff, capture exact wording and identify:
- required users;
- required outputs;
- constraints;
- prohibited approaches;
- scoring implications;
- hidden implementation risks.

### B. Problem validation
Find credible primary/authoritative sources for:
- problem prevalence;
- current workflows;
- user pain points;
- existing interventions;
- measurable impact opportunities.

### C. Competitive landscape
For the exact prompt:
- identify direct competitors;
- identify adjacent tools;
- compare capabilities;
- locate gaps;
- avoid copying distinctive product behavior or assets.

### D. Technical feasibility
Verify:
- model availability;
- input modalities;
- context/tool support;
- deployment limitations;
- latency/cost constraints;
- licensing;
- data/API terms.

### E. Evaluation
Define tests before tuning:
- representative fixtures;
- benign/adversarial cases;
- expected outputs;
- measurable metrics;
- known failure categories.

## Candidate concept (not committed)

A previous brainstorming direction was **AEGIS as a multimodal AI-assisted cyber-risk analyzer**: user-provided message/URL/screenshot/QR → extraction → deterministic signals → ML/LLM reasoning → risk/explanation → recommended action.

This remains only a **candidate hypothesis**. It must be discarded or adapted if the official prompt does not support it.

## Source discipline

Prefer:
1. official organizer rules/prompt;
2. primary institutional/technical sources;
3. official provider documentation;
4. reputable secondary analysis;
5. community discussion only as contextual evidence.

Never turn an unverified idea into a repository requirement.
